# Other session's Monarch Studio — technical and visual inspection

Read-only inspection of `arena/b65b8a07-top1` at exact commit `3395e16a9150e88d299a2bef5ee4e37936419c3d`; no branch switch and no changes to the other branch. `monarch-studio/` is the site/player and notes; the actual render implementation lives in `tools/demo-render/`, `tools/render-demos.mjs` and `tools/air-crush-score.mjs` at the repository root. The can project is an independent reference for craft/pipeline, not an animal 3D benchmark or finished Gecko production.

## What the code actually does

- `package.json` declares Three.js, Vite and playwright-core. `render-demos.mjs` builds the renderer with Vite, launches headless Chromium using Playwright, and requests `window.top1Frame(frame / 24)` for each output frame. JPEG bytes stream to FFmpeg; H.264 video and AAC mix are encoded to a fast-start MP4. The rendering resource interception restricts requests to the locally built compositor.
- `main.js` creates Three.js WebGL renderer and scene, composes text on a Canvas 2D final image and optionally uses depth/lens processing and two within-shot sub-exposures for selected fast movements. Default air-crush 3D plate is rendered at `.64` of film dimensions and upscaled on the 1080×1920 canvas; title artwork remains full canvas resolution. `TOP1_FULL_QUALITY=1` selects full raster on rebuild; existing file is not automatically native-resolution 3D.
- `air-crush.js` builds actual procedural 3D objects: custom BufferGeometry can sidewall, separate lid/rim/base, bath, fixture, steam and water components. Texture maps include procedurally painted can branding. `air-crush-motion.js` calculates timed rig pose, buckle deform, foot position and water event. Its comments state the collapse is authored, not a finite-element prediction; pressure graphics are illustrative. `air-crush-vfx.js` handles visual water/splash and pressure marks.
- `air-crush-score.mjs` synthesizes timed stereo lab/splash/metal layers. The committed Urdu narration stem is separately included and FFmpeg mixes it with the synthesized score. Production notes describe auditioned voice and −14.5 LUFS / −0.6 dBTP; not independently heard or remeasured here. This can film uses Urdu voice/Roman Urdu captions, whereas Monarch Cam's film language remains English.
- `monarch-studio/PRODUCTION.md` provides a shot-by-shot timing table and explains distinctions between source research and authored depiction. This is useful as a practice for keeping science and cinematic approximations separate.

## Transfer to Monarch Cam

Use the architecture as a production reference: explicit per-shot camera/lighting, deterministic time-based render, full-frame 24 fps export, original geometry and materials, a shared cue sheet, authored audio synced to events, and tests for important visual continuity. Prototype at reduced raster then choose a deliberate final setting; do not call an upscale a native-resolution plate. For gecko, replace can-specific geometry/deformation with an appropriate pad-bearing animal/foot representation and a scientifically cautious macro explanation; don't assume the can rig, Urdu script, materials, or product aesthetic automatically fit Gecko. Existing candidate gecko model quality, biology, audio, actual animal 3D benchmarks and rights remain open. No Batch 2 pass follows merely from another project's functioning pipeline.
