# Encrypted Actions report bridge

This agent-side workaround transfers the `REPORT.md` from a completed research artifact when GitHub's storage redirect is unreachable but the GitHub API is reachable. It requires an unexpired artifact, `gh` authenticated to the same repository, OpenSSL, Git push access to this session branch, and Actions enabled. It is not a YouTube or analytics integration.

1. `python3 tools/extinct-life/report_bridge.py prepare SOURCE_RUN_ID` generates a fresh local private key and public certificate in `.cache/extinct-life-report-bridge/SOURCE_RUN_ID/` and updates the bridge workflow for that source run. Do not lose the private key before collecting. Do not commit it.
2. Inspect the workflow diff. Commit and push **only** `.github/workflows/extinct-life-report-bridge.yml` to the current branch. Its path-filtered push starts a transfer run. Find the matching run by commit SHA. Do not use the large `gh run watch` annotation output as a data channel.
3. After it succeeds, `python3 tools/extinct-life/report_bridge.py collect SOURCE_RUN_ID BRIDGE_RUN_ID` checks the run's branch, result and committed source ID, reassembles the encrypted chunks through the check-annotations API and decrypts `REPORT.md` under that cache directory. Then read it there. No user download is needed.
4. Delete local report, certificate and private key when no longer needed in accordance with YouTube's policies; don't commit them. The original artifact has one-day retention. The bridge run's logs/annotations contain encrypted ciphertext, not plaintext, and follow GitHub's own log retention unless separately deleted. Treat the private key as sensitive. `.cache` may not persist across sessions; generate a new key and bridge workflow for another transfer instead of assuming an old key exists. If reusing the same source run, clean its old cache directory after finishing first.

This was designed for small report files. The workflow rejects more than 10 chunks (25,000 base64 characters) before emitting any; a larger report needs a different bounded transport. This does not transfer raw JSON, and is not authenticated encryption: verify run identity and trust GitHub's TLS/API and runner; do not use it for secrets, private channel/Studio data or untrusted repositories. The workflow has actions-read/contents-read permissions and no YouTube key. It only runs when its workflow path changes on the session branch. The certificate is public, the private key stays local. No automated run deletion or periodic research schedule is configured.
